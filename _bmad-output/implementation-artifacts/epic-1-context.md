# Epic 1 Context: Socle outillé et garde-fous vérifiés par le code

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Projet greenfield : cet epic crée le squelette `uv` / Python 3.12 du paquet `slmsp` et transforme les règles bloquantes de la nuit en code testé, avant tout appel réseau ou payant. Il pose les couches d'import vérifiées par AST, le noyau partagé (configuration, secrets, erreurs, JSON canonique, ressources machine), les runs immuables, la passerelle réseau unique avec Liste blanche et journal, et le registre de budget persistant qui s'arrête au plafond. Cet epic technique est assumé comme tel : sa valeur est que les garde-fous ne dépendent plus de la discipline des agents, et toutes les autres stories en dépendent.

## Stories

- Story 1.1 : Squelette du projet et outillage
- Story 1.2 : Noyau : configuration, secrets, erreurs, JSON canonique et ressources partagées
- Story 1.3 : Noyau : runs immuables, lecteur contrôlé, ports, messages et évènements
- Story 1.4 : Passerelle réseau unique (profils, Liste blanche, journal des Requêtes sortantes)
- Story 1.5 : Registre de budget persistant avec arrêt au plafond

## Requirements & Constraints

- **Règles bloquantes (jamais d'exception)** : Claude ne produit aucune Donnée d'entraînement (y compris les fixtures) ; aucune publication (ni push, ni Hugging Face, ni upload) ; seuls services réseau autorisés : Hugging Face (téléchargement), PyPI et GitHub (lecture), API Mistral, API Anthropic, `mcp.data.gouv.fr`, `www.data.gouv.fr`, hôtes de la Liste blanche ; ajouts tracés : `download.pytorch.org` (torch CUDA) et GET seul sur la page des conditions de Mistral. Budgets durs : Mistral 30 € (génération 25, second juge 5), Anthropic 10 €. Ne jamais supprimer ni réécrire un artefact.
- **Mode et confidentialité** : en Mode hors ligne forcé, aucune requête ne part, même pas la sonde `GET /health` ; en hors ligne détecté, seule la sonde passe. Seules des Requêtes sortantes journalisées quittent le poste.
- **Liste blanche** : configurable par fichier, correspondance exacte du nom d'hôte (insensible à la casse et au point final) ; HTTPS seulement ; IP, sous-domaine piégé (`mcp.data.gouv.fr.exemple.com`) ou hôte voisin (`evil-data.gouv.fr`) bloqués et journalisés. Hôtes v1 : `mcp.data.gouv.fr`, `www.data.gouv.fr`, `www.service-public.gouv.fr` (+ `www.service-public.fr`), `www.legifrance.gouv.fr`, `entreprendre.service-public.gouv.fr` (+ `.fr`), `lannuaire.service-public.fr`.
- **Reproductibilité** : chaque exécution est rattachée à sa configuration, sa graine, son environnement et le SHA de ses entrées.
- **Définition de « terminé »** : `ruff check`, `ruff format --check` et `pytest` passent ; marqueurs `reseau`, `gpu` et `lent` exclus par défaut ; aucune API payante dans les tests (transports factices injectés) ; une garde de test fait échouer toute connexion hors boucle locale ; une story ne touche que ses fichiers ; tests miroir sous `tests/<paquet>/` ; un commit local par story `feat(<epic>): <story> (story X.Y)` ; après deux échecs sur un même problème, consigner, contourner en marquant `degrade`, passer à la suite.

## Technical Decisions

- **Couches (import strictement vers le bas, jamais entre paquets d'une même couche)** : core (0) < net, budget (1a) < inference, index, mcp, mistral (1b) < harness, judge (2) < fetch, indexation, evaluation, benchmarks, measure, data, train, compare (3) < cli, app (4). Les adaptateurs reçoivent leurs dépendances par injection (`net` reçoit un `ModePort`, n'importe jamais `harness`).
- **Fermeture runtime** (calculée transitivement depuis core, net, budget, inference, index, mcp, harness, app) : n'importe jamais torch, transformers, trl, peft, bitsandbytes, unsloth, lm_eval, bfcl_eval, anthropic, mistralai, datasets, duckdb, pyarrow. Extras uv : `fetch`, `data`, `judge`, `bench`, `train`, `app` ; Unsloth et bfcl-eval hors du lock principal.
- **Bannissements** (ruff `TID251` + test AST) : `anthropic` hors `judge/`, `mistralai` hors `mistral/`, clients HTTP (`httpx`, `httpx2`, `requests`, `urllib.request`) hors `net/`, fonctions d'upload de `huggingface_hub` et `push_to_hub` partout ; `data` et `train` n'importent jamais `judge` et ne lisent des fichiers que via `core.artefacts.lire`. `eval/calibrage/build_calibrage.py` et `eval/outils/` sont exclus de `TID251`.
- **torch** : tiré d'un index PyTorch CUDA déclaré `explicit = true` dans `[tool.uv.index]` et relié par `[tool.uv.sources]` (cu130, sinon cu128).
- **CLI** : paquet `slmsp/cli/` (argparse, point d'entrée `slmsp.cli:main`), un module par sous-commande exposant `enregistrer(sous_parseurs)`, chargé sans modifier `__init__.py` ; module absent = « commande non implémentée », code 2. `sys.stdout` en UTF-8. Codes de sortie nommés : 0 succès, 1 erreur, 2 usage, 3 budget épuisé, 4 manifeste invalide, 5 ressource occupée.
- **Erreurs** : hiérarchie unique sous `SlmspError`, chaque sous-classe porte son `code_sortie` ; la CLI affiche un message sans trace technique.
- **Configuration et secrets** : toute valeur réglable dans un TOML de `config/`, lu par `tomllib`, validé par pydantic `extra="forbid"` (modèle dans `<paquet>/config.py`). Secrets lus par `dotenv_values`, en `SecretStr`, jamais dans `os.environ`, remis seulement aux fabriques de clients ; sous-processus lancés sans `*_API_KEY` ni `HF_TOKEN`, avec télémétrie coupée (`HF_HUB_DISABLE_TELEMETRY`, `WANDB_MODE=disabled`, `DO_NOT_TRACK`) et `HF_HOME=models/.cache-hf`.
- **Primitives de `core`** : JSON canonique (clés triées, séparateurs compacts, `ensure_ascii=False`, octets UTF-8), SHA-256 hexadécimal minuscule ; `SLMSP_VAR_DIR` (défaut `%LOCALAPPDATA%\slmsp\var\`, hors dépôt, unique par machine) ; SQLite toujours en WAL avec `busy_timeout` de 30 s ; verrou GPU exclusif `gpu.lock` (PID mort récupérable).
- **Artefacts immuables** : `runs/<type>/<run_id>/`, `run_id` = `AAAAMMJJ-HHMMSS-<slug>-<4 hex>` ; `run.json` (`RunManifest`) jamais réécrit ; statut en ajout dans `etat.jsonl` (`en_cours`, `complet`, `partiel-budget`, `partiel-erreur`, `interrompu`, `degrade`) ; reprise en ajout seul ; vérification d'espace libre avant toute écriture de plus de 1 Go. Les schémas d'artefacts vivent dans `core/schemas/`, un module par schéma, base commune avec `schema_version`, sans réexport, créés par la première story qui en a besoin.
- **Lecteur contrôlé** : listes d'accès par lecteur (`data`, `train`), chemins résolus (liens et `..`) ; `eval/**`, `runs/eval-*` et le cache des verdicts sont toujours refusés à `data` ; `train` ne lit que `data/train/`, `models/` et le journal Mistral en lecture seule.
- **Ports et formats du Harnais** (définis dans `core`) : `LlmPort`, `EmbedderPort`, `VectorStore`, `ToolPort`, `NetGate`, `ModePort`, `JournalRequetes` ; messages au format OpenAI (`system`, `user`, `assistant`, `tool`, `tool_calls` structurés) ; évènements typés sérialisables en aller-retour.
- **Passerelle réseau** : fabrique unique `slmsp.net.client(profil, ...)` dont le transport gardé vérifie chaque requête avant le transport interne ; clients injectés dans les SDK (MCP, anthropic, mistralai, `huggingface_hub.set_client_factory`) ; relances des SDK désactivées ; chaque saut de redirection revérifié et journalisé. Profils : `assistant` (Liste blanche), `outillage` (GET/HEAD vers les services autorisés, POST seulement vers `api.mistral.ai`, `api.anthropic.com`, `mcp.data.gouv.fr`), `aucun` (tout refusé). Délais par défaut : MCP 10 s, sonde 3 s. Entrée de journal figée : `horodatage`, `profil`, `hote`, `methode`, `outil`, `termes`, `statut` (`envoyee`, `echouee`, `bloquee-liste`, `bloquee-mode`), `mode`, sans en-têtes, corps ni secret ; implémentation SQLite par défaut, remplaçable en J4 sur le même schéma.
- **Budget** : `budget.sqlite` dans `SLMSP_VAR_DIR`, `campagne_id`, aucune remise à zéro. Réservation du coût pire cas (entrée majorée + `max_tokens` au tarif de sortie, modèle résolu et mode) en `BEGIN IMMEDIATE` ; refus si dépensé + réservé + marge dépasse le plafond du sous-poste ou du poste ; régularisation au coût réel, ou pire cas conservé si l'appel échoue sans `usage` ; tarif inconnu = erreur, sans défaut ; une réservation par tentative ; réservations orphelines (PID mort, hors lot) régularisées au pire cas ; lots batch persistés avant attente. Tarifs de départ prudents et datés (Claude Opus 5.5 : 4 $ / 20 $ par million de tokens, −50 % en batch ; Mistral marqué « à vérifier par Anaël »). Imputation : `juge-second` → `mistral.juge` ; `generation` et `validation` → `mistral.generation`.
- **`.gitignore`** : ignorer `index/`, `var/`, `vendor/`, `models/`, `data/raw/`, `data/train/*/train.jsonl`, `runs/**/checkpoints/`, `runs/**/adaptateur/`, `*.gguf`, `*.safetensors`, `.env` ; versionner `run.json`, `scores.json`, `verdicts.jsonl`, les MANIFEST de `data/train/`, `data/registre-licences.toml` et `.env.example`. Les anciennes règles `runs/` et `checkpoints/` en bloc disparaissent.
- **Conventions** : termes du domaine en français sans accents dans le code ; `pathlib` partout, encodage explicite, jamais le `python` du PATH (toujours `uv run`) ; JSONL UTF-8 LF ; dates ISO 8601 avec fuseau ; budget en euros.

## Cross-Story Dependencies

- Chaîne : 1.1 → 1.2 → 1.3 → 1.4 ; 1.5 dépend seulement de 1.2 et peut tourner en parallèle de 1.3 ou 1.4 (zones de fichiers disjointes). La story 5.2 (fonctions de texte) ne dépend que de 1.1.
- La story 1.1 déclare d'avance toutes les sous-commandes (`fetch`, `index`, `ask`, `mcp`, `eval`, `bench`, `measure`, `data`, `train`, `export`, `compare`, `budget`) : les epics suivants ajoutent leur module `cli/<commande>.py` sans toucher `cli/__init__.py` (que seule 1.2 modifie ensuite).
- En aval, 1.4 débloque le téléchargeur et l'inférence (2.1, 2.2) et le client MCP en direct (3.3) ; 1.3 débloque les outils MCP (3.1), les Tâches du Harnais (4.1), le lecteur d'items (5.1) et le registre des licences (9.1) ; 1.4 et 1.5 sont requis par le Juge Claude (5.4) et tout client payant.
- Le `ModePort` est consommé par `net` dès 1.4, mais ses implémentations (`ModeSonde`, `ModeFixe`) arrivent avec le Harnais (Epic 4) : tester avec des doublures.
- Les verrous AD-3 posés ici (imports, lectures) sont complétés par les stories 9.2, 9.3 et 9.6.
